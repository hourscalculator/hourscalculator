## 1. 这是一款什么产品？

用户填写上班、下班与休息时间，网站计算工时；如填写时薪，还能估算工资。可以按周、双周或其他日期范围查看，支持多人记录、打印、CSV 导出和分享报告。

**产品原则：首次使用尽量简单；复杂工作安排仍有完整入口。** 普通需求用户可通过四步向导填写；复杂需求用户可用 Detailed（详细填写）。两种填写方式使用同一份数据，最终进入同一套 Report（结果报告）。

### 四类典型用户

| 谁在使用     | 想完成什么           | 最常见操作           | 主要入口    |
| -------- | --------------- | --------------- | ------- |
| 小时工      | 核对这周上了多少小时、估算收入 | 周一至五填统一时间，偶尔改一天 | 手机、快速填写 |
| 自由职业者    | 给客户核对工作记录、准备开票  | 一天几段工作，记录客户/项目  | 电脑、详细填写 |
| 小老板 / HR | 核对一周或两周工时及加班费   | 检查日期、休息、加班规则    | 电脑、详细填写 |
| 小团队负责人   | 一次核对多名人员的工时     | 每人一张卡，查看合计      | 电脑、详细填写 |

## 6. 所有页面共用的计算规则

下文统一用“工时”表示可以计入计算的净工作时间。

### 6.1 工作时间和休息

1. **当日净工时 = 当日各段工作时间之和 − 工作段内的无薪休息时间**。
2. 有薪休息仍算工时；两段工作之间没工作的间隔无需再扣一次。
3. `09:00–12:00` 和 `13:00–17:00` 是 **7小时**。若 `09:00–17:00` 另有 **30分钟无薪休息**，是 **7小时30分钟**。
4. 下班时间早于上班时间表示跨到第二天；相同时间视为无效的零时长班次。
5. **自动休息的线上说明**：在中午生成可编辑的无薪休息时间段；用户手动编辑休息后，自动休息会关闭。必须避免同一段休息重复扣除。
6. 时间计算使用实际输入的分钟；不使用经过四舍五入的展示值来反算工资。
7. 从 Quick Fill 进入 Detail 时，分钟数休息继续以分钟数显示；不推断具体起止时间。需要记录实际休息时段时，由用户在 Detail 填写。

### 6.2 工时展示

- 同一工时要同时能看 `hh:mm` 和 `Decimal`。例如 `7:30 = 7.50小时`、`24:03 = 24.05小时`。
- 修改小数显示精度或按15分钟的**显示舍入**，不得改变实际工时和工资计算。
- 线上帮助说明按本地日历日期与钟表分钟处理，不做设备时区换算；夏令时切换不自动修正。

### 6.3 加班和工资

**新建快速填写默认关闭加班。** 详细模式在旧PRD里记载新建默认“周超40小时”；是否与实际首页默认一致，仍须实机核验。已有草稿切换模式时，保留它原有的加班设置。

| 模式         | 计算方式（线上帮助说明）                                           |
| ---------- | ------------------------------------------------------ |
| 不计算加班      | 所有净工时按普通时薪计算                                           |
| Weekly     | 每个工作周超过40小时的部分按1.5倍计算；双周不把80小时作为单一门槛                   |
| Daily      | 每个工作日超过8小时的部分按1.5倍计算                                   |
| California | 超过8至12小时按1.5倍，超过12小时按2倍；另考虑连续第七个工作日与工作周规则，避免重复计算同一加班溢价 |

- 统一时薪可留空：不填也能得到工时，金额显示“未设置时薪”，不能当作零工资。
- 工资估算基于实际分钟与所选时薪，最终按货币最小单位（如美元分）处理。
- 统计范围外若有影响同一工作周加班的相邻工时，应参与计算；结果只展示选择范围内的记录，并在缺少上下文时提示估算可能不完整。
- 网站提供的是**估算的税前工资**，不处理税、奖金、特殊行业豁免、meal penalty 等情形。

## 7. 数据、分享及安全边界

- 【线上可核对】草稿保存在当前浏览器；清理浏览器数据或无痕模式可能导致丢失。当前不要求登录、跨设备同步或服务端账户。
- 【线上可核对】分享时把当次记录做成**只读快照链接**。持有链接的人可以阅读快照；链接不能撤销，也不自动随本地修改更新。
- 【线上可核对】审批回执由链接持有人填写并生成回执链接，**不验证真实身份**；不能描述为带身份认证的电子签名。
- 【本次确认的目标】两种填写方式、所有卡片和报告必须共用一套输入/计算结果；修改统一时薪后全部卡片重新计算。
- 清空或覆盖已有工时要有明显警告；取消时原数据不变。无效输入必须提示错误，不应生成有误导性的可交付报告。

## 8. 页面体验要求

- 手机首屏首先呈现工具入口与必要输入，不让长篇帮助说明挤在操作区前面；说明和 SEO 正文可保留在主要操作区后方。
- 第一次访问自动弹出四步向导；之后首页有明显“快速填写”按钮，Detailed 和 Advanced settings 仍可找到。
- 高级设置默认折叠；展开后保留全部已有功能。
- 手机上能点击、输入、返回、展开逐日详情，不依赖悬停；时间轴之外必须能用文字输入时间。
- 输入错误应指出具体日期和字段，不仅显示一个笼统的失败提示。
