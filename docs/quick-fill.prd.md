# 快速填写 PRD

## 目标

让每天工作时间较固定的用户，通过四步快速完成填写并查看工时和工资。

## 需求

适用于单人、每天一段工作的记录。首次打开即可填写，过程中可切换到Detail处理复杂排班，完成后进入共用结果页。

## 功能

| 功能 | 用户能做什么 |
| --- | --- |
| 入口和四步 | 首次进入向导，可转Detail；四步依次为工作日、上下班、无薪休息、可选信息。Back保留值，首步Back禁用，Continue成功才推进，第4步Calculate进入共用结果。 |
| 默认和逐日权威 | 新默认08:00–16:30、休0，初始化周期前五日。未逐日选择时默认写入未定制日期。显式展开逐日后使用逐日填写的时间，折叠仅改变显示，顶部默认输入不能覆盖逐日值。 |
| 日期选择 | Period确认后按新旧开始日偏移移动工作记录和工作内容的日期，移除新范围之外的工作记录和逐日设置。取消不变，新增范围不自动填满。工作内容随日期一起移动，移出范围的内容保留在记录中。 |
| 可选与校验 | Name、Period、Rate、Overtime在第4步。每选中日上下班完整且休息不超过时长。错误留本步并定位可见输入，修复后继续。新建快速填写默认不计算加班，重新打开已有草稿时保留其加班设置。 |
| 关闭恢复与复杂草稿 | 关闭保存当前步和值，重开恢复，刷新恢复浏览器草稿。复杂多卡、多段、手动区间休息或不支持日周界进入向导前提示，取消留Detail，确认新建替换须有清楚警告。 |
| 同步和结果 | Detail编辑兼容卡后向导读取最新值，向导提交回写同一份工时记录。新计算需要替换确认，取消保留。共用结果页只读，返回编辑保留当前输入，分享和导出与结果页一致。 |

## 填写与显示规则

| 字段 | 默认与必填 | 可见及可编辑 | 范围与校验 |
| --- | --- | --- | --- |
| 工作日 | 周期前五日，至少一天 | 第1步复选可编辑 | 取消一天移除该日记录，新增日继承默认 |
| 默认In/Out | 08:00 AM/04:30 PM，必填 | 第2步；使用逐日填写后顶部只展示 | 格式合法且不相同，跨午夜允许 |
| 逐日In/Out | 继承默认，已选日必填 | 第2步展开可编辑 | 每日校验，折叠不撤销逐日选择 |
| 默认/逐日Break | 0分钟，必填数值 | 第3步0/30/60/Custom及逐日输入 | 0–1439整数且不超班长；定制日不被默认覆盖 |
| Name | 空，可选 | 第4步可编辑 | 最多200字符，每卡 |
| Period | 当前一周，可选修改 | 第4步日期弹窗 | 含首尾的有效范围 |
| Rate/Overtime | 空费率/不计算加班 | 第4步可编辑 | 费率0–1000000，空费率保留工时，已有草稿保留设置 |

## 页面与操作

每次显示一步，依次填写工作日、上下班时间、休息和可选信息。返回可修改前一步，关闭后可以继续填写。第4步点击计算进入结果页。

输入错误时在对应位置提示，改正后可以继续。取消操作保留原值。已填写内容自动保存在当前浏览器，刷新后恢复。手机上应能看清内容并操作所有按钮。共同的计算和保存规则见[公共说明](README.md)。

## 测试

以下是验收时要检查的场景。

| 场景 | 怎么操作 | 应该看到什么 |
| --- | --- | --- |
| 四步填写 | 选择周一至五，08:00–16:30，休30分钟，时薪$20，选择周加班；周五结束改18:00 | 41小时30分钟，普通工资$800，加班工资$45，总$845 |
| 逐日填写 | 展开逐日时间，把周一结束改成17:00，再折叠 | 周一保留17:00；折叠后计算仍使用逐日时间 |
| 默认继承 | 未定制的日期使用08:00–16:30，把默认结束改17:00 | 未定制日期更新为17:00，已单独填写的日期保持原值 |
| 返回和关闭 | 填写到第3步，返回第2步，再关闭重开并刷新 | 已填内容保留，能接着填写 |
| 日期调整 | 把11月9–15日改为16–22日，再缩到16–18日 | 已有时间随日期后移7天；缩小时仅保留新范围内工作记录 |
| 取消日期选择 | 打开日期选择，修改后取消 | 日期和工作记录保持原值 |
| 双向同步 | 快速填写周一08:00–16:30休30分钟，去Detail改结束为17:00，再返回 | 周一显示17:00，净工时8小时30分钟 |
| 复杂记录 | 从有多段工作的Detail进入快速填写，取消替换提示 | 返回Detail，原记录保留 |
| 校验 | 清空某个已选日的下班时间，点击继续，再补齐 | 提示该日需补全，补齐后可进入下一步 |
