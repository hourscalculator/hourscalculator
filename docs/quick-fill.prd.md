# 快速填写 PRD（Quick Fill / Simple）

> 版本：V1.0｜对应总览：[README](README.md)  
> 目标用户：主要是手机上的小时工或排班较固定的个人。  
> **一句话目标**：用户只需选工作日、填上下班、填休息，就能看到工时；需要时再填姓名、时薪和加班。

## 1. 使用场景

例：用户周一至周五通常08:00上班、16:30下班，午休30分钟，只有周五下班延迟到18:00。他不应被迫逐天填写五次，也不应为了改周五而丢失其他日期的时间。

快速填写处理**一人、常规一周上班为主**的情况。一天多段工作、多个员工、具体休息起止时间或复杂边界，在 Detailed 中处理。

## 2. 入口：第一次进入发生什么

1. 新用户第一次进入网站，如果没有已有草稿，**自动打开四步填写弹窗**。
2. 以后打开网站不强制重复弹出，首页始终有清楚可见的 **Quick Fill / Calculate Hours** 入口，可手动打开。
3. 弹窗会提供 **Detailed Calculator** 入口；不需要用户先走完向导才能进入详细模式。
4. 用户关闭弹窗后保留已填写的值和当前步骤；重新打开继续。刷新后同样能恢复（浏览器允许保存时）。
5. 首屏以工具为主；长篇使用说明和帮助文字放在主要操作区之后。

**QF-02【旧PRD记载，作为目标验收】**：每次只显示一步。`Back` 返回上一步并保留值；首步不能再后退。`Continue` 检查当前数据，通过后才前进。第4步点击 `Calculate` 进入共用的只读 Report。

## 3. 四步弹窗具体做什么

### 第1步：选择哪几天工作（Workdays）｜QF-03

- 默认选择**当前统计周的周一到周五**，用户可勾选或取消任一天；至少选一天。
- 取消某天，**本次准备计算的记录**不应再把该天算入；再次选中时，若未单独定制时间，用默认班次。
- 显示所选择的日期，避免用户以为填写了错误的一周。

### 第2步：填写上下班时间（Work hours）｜QF-04

- 新建默认上班 **08:00 AM**，下班 **04:30 PM（16:30）**，合计8小时30分钟的班次时长；此时尚未扣休息。
- 用户通常只需要在顶部填写一次“默认上班/下班时间”，所有未单独修改的选中日期都使用它。
- 有 **Customize each day / 逐日修改** 展开项；展开后可调整某一天的时间。
- **某一天一旦单独修改，之后即使折叠逐日列表，该日仍使用单独时间**。更改顶部默认时间只影响未单独修改的日期。
- 用户可输入合法的12小时或24小时时间；跨午夜班次允许（例如22:00–06:00为8小时）。上/下班同一时间算错误。

### 第3步：填写无薪休息（Unpaid break）｜QF-05

- **新建默认0分钟**；可选0、30、60分钟或自定义分钟数。
- 默认休息分钟数应用到未单独设置休息的选中日期。
- 支持展开逐日改休息分钟；某日单独改过后，改顶部默认休息不覆盖它。
- 休息不能为负数、不能大于当天班次时长；一旦不合法，提示具体日期并留在本步。
- 简单模式的休息是**扣除分钟数**；需要设置休息从几点到几点、或带薪休息，进入 Detailed。

### 第4步：补充信息并计算（Optional details）｜QF-06

| 字段 | 新建默认 | 必须填写吗？ | 用来做什么 |
| --- | --- | --- | --- |
| Name（姓名） | 空 | 否 | 让结果页能看出是谁的工时 |
| Period（统计日期） | 当前一周 | 有默认值，可以改 | 明确本次统计哪几天 |
| Hourly rate（时薪） | 空 | 否 | 填后可以估算工资；空着也能算工时 |
| Overtime（加班） | **Off / 不计算加班** | 否 | 需要时可选 Weekly、Daily 或 California |

- 时薪是一处全局设置；在 Detailed 增加其他工时卡后也使用同一个时薪。这里不能产生独立的“本卡专属时薪”。
- 第4步按 `Calculate` 后，按实际净分钟计算并进入 Report；可返回编辑，不能丢草稿。
- **已有草稿进入向导时保留其原设置**，不因为“新建默认”而重置时薪或加班。

## 4. 修改日期：切换到新的一周｜QF-07

**【本次确认的目标，覆盖旧PRD中“整体平移并删除越界日期”的默认做法】**

例：上一周周一至周四 `08:00–16:30`，周五 `08:00–18:00`。用户选择下一周时，新周周一至周四初始 `08:00–16:30`，新周周五初始 `08:00–18:00`。

要求：

1. **切到新的一周时，以上一周同星期几的上下班时间为初始值**；上周单独改过的日期也要保留对应差异。
2. 上一周的原始记录保留，用户之后重新选回上一周，仍能看到上周数据。
3. 新一周若已存在记录，必须显示该周原本已保存的记录，不得用“复制上一周”覆盖它。
4. 没有可复制的上一周记录时，使用新建默认时间 `08:00–16:30`。
5. 选择日期后取消，不改变当前日期与记录。
6. **本次只确认复制“上班/下班时间”**。休息、工作内容、客户或项目是否复制，尚未约定；不要偷偷把这些内容加入复制逻辑。
7. 单周以外的日期操作（双周/自定义范围）保留原有日期选择能力，但新“复制上一周”策略尚未扩展到这些范围，见 README 的 OPEN-03。

> 与旧文件的差异：旧PRD说“改 Period 后按开始日期偏移平移现有记录，移出范围就移除”。这可能破坏历史数据。**用户本次确认了按新周复制时间、保留旧周**；正式实现以此处为准。

## 5. 切换 Detailed、关闭、重新打开｜QF-08

- 用户在第1～4步都可以进入 Detailed 处理复杂情况；已经输入的数据要带过去。
- Quick Fill 中输入的无薪休息分钟数进入 Detailed 后仍显示为分钟数；不自动推断休息的起止时间。
- Detailed 修改同一张兼容的工时卡（例如周一下班从16:30改为17:00），再回到向导时应读取**修改后的**时间。
- 已有多个工时卡、某天多段工作、手动起止区间休息或特殊工作日边界时，如果返回向导不能完整表示这些数据，应**先明确提示**：继续可能会替换复杂记录；用户取消则留在 Detailed，不能静默丢数据。
- 从报告页返回编辑，或关闭向导再打开，不应自动清空。
- 选择 Clear / 新建替换已有草稿，先提示将清掉什么；取消不变。

## 6. 错误处理｜QF-09

| 情况 | 预期提示和结果 |
| --- | --- |
| 没选工作日 | 提示“至少选择一天”，不能继续 |
| 上班或下班缺一项 | 指向具体日期和具体字段，不能继续 |
| 上下班同一时刻 | 提示零时长班次无效 |
| 休息超过班次长度 | 告知当天工时不足以扣除该休息 |
| 时间格式不合法 | 保留原输入，要求改正，不自动猜成合法时间 |
| 浏览器保存不可用 | 当前页面继续可用，告知刷新后可能丢失 |
| 点击返回、关闭或取消确认 | 不撤销用户之前已完成且有效的填写 |

旧PRD记录的字段限制：姓名最多200字符；时薪范围为0～1,000,000，保留最多两位小数；休息为0～1439整数分钟。这些是旧文档规则，本次无法从静态网页逐项验证，Codex 修改前应做边界测试。

## 7. 验收用例：按这个顺序人工测试

| 编号 | 怎么操作 | 应该看到什么 |
| --- | --- | --- |
| QF-T01 首访 | 清理测试浏览器中的本站草稿，第一次打开首页 | 四步弹窗自动出现；页面仍有可见的手动快速填写入口 |
| QF-T02 默认值 | 全新进入第2、3、4步 | 08:00–16:30；休息0分钟；加班关闭；时薪为空 |
| QF-T03 典型小时工 | 周一至四08:00–16:30，周五改18:00，五天休30，$20/h，Weekly | 周总41:30，普通40h/$800，加班1:30/$45，总$845 |
| QF-T04 逐日时间 | 周一单独改17:00，折叠，再把顶部默认改18:00 | 周一保持17:00，其他未定制日期更新为18:00 |
| QF-T05 逐日休息 | 周一单独设60分钟，其余默认30，折叠再展开 | 周一仍60分钟，其余30分钟 |
| QF-T06 新周复制 | 上周周五单独18:00，下周为新周，切换 | 下周周五初始18:00，其他日按上周对应星期复制；上周记录依旧存在 |
| QF-T07 新周已有数据 | 新周已填周五17:00，再从上周切换过去 | 显示新周已有的17:00，不被上周18:00覆盖 |
| QF-T08 返回关闭 | 填到第3步→退第2步→关闭→刷新→重开 | 步骤与有效填写值保留 |
| QF-T09 双向更新 | Simple填周一08:00–16:30/休30→Detailed改17:00→Simple | 周一下班17:00，当日净工时8:30 |
| QF-T10 复杂数据保护 | Detailed建立一天两段工作→回Simple→取消提示 | 复杂记录仍完整，保留在Detailed |
| QF-T11 错误 | 清空已选日的下班字段→Continue→补齐 | 错误指向对应日期；补齐后可以继续 |
