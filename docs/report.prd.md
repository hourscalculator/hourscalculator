# 结果报告 PRD（Report / Share / Export）

> 版本：V1.0｜对应总览：[README](README.md)  
> **一句话目标**：用户和接收人都能看清楚“哪一天做了多久、总共多少工时、工资怎么算出来的”，并方便保存、分享与核对。

## 1. 报告从哪里来｜RPT-01

- 快速填写第4步点击 `Calculate`，进入 Report。
- Detailed 完成填写后，可以打开/预览同一套 Report。
- 用户点分享链接、审批快照链接，看到的是生成链接当时的**只读记录**。
- 无论从哪种填写入口进入，报告的工时、工资、日期和休息规则都必须一致。
- 报告只读；需要改上下班、休息或时薪，返回填写界面编辑，修改后再看更新后的报告。

## 2. 报告要按什么顺序显示｜RPT-02

对每一张工时卡，依次显示：

1. **是谁的记录**：有值时显示 Name、Client、Project；留空的可省略。
2. **统计日期**：明确起始日期和结束日期，且两端都包含在统计内。
3. **每日明细**：日期、上班/下班时间、休息、当天净工时；多段工作要看得到每段。
4. **工作内容**：某天填了 Content 才显示相应内容；完全没填可不展示空列。
5. **本卡合计**：净工时、普通工时、加班工时、双倍工时，以及估算工资。
6. **全部卡合计**：多人的工时、相应工资合计。
7. **交付动作**：打印/另存PDF、导出CSV、生成分享快照。

【旧PRD记载】Name与Period分行；Hours逐日展示；Rate和Overtime以只读样式展示。具体视觉排版可按当前线上样式保留，核心字段不能缺。

## 3. 工时怎么显示｜RPT-03

| 字段 | 用户应该理解成什么 | 规则 |
| --- | --- | --- |
| In / Out | 上班和下班时间 | 每段单独展示；未填完整的不生成有效报告 |
| Break | 当天休息 | 保留有薪/无薪信息，只有无薪休息扣净工时 |
| Hours | 实际可计算的净工时 | 按真实分钟求和，不使用展示舍入后的数字累加 |
| `hh:mm` | 小时:分钟 | 例如 7:30 表示7小时30分钟 |
| Decimal | 十进制小时 | 7:30 对应7.50，10:15对应10.25 |
| Content | 当日工作记录 | 仅有值时出现，并绑定正确日期 |

- 空白日期可显示无工时；某一段只有上班没有下班属于错误，不能悄悄算成0小时。
- 所有用户输入的文字只当作文字显示，不能当成网页代码执行。

## 4. 普通、加班和工资怎么列｜RPT-04

报告要使用户能顺着明细核算金额，而不只给一个大数字。

- **REG (Regular)**：按普通费率计算的工时和金额。
- **OT (Overtime)**：按1.5倍、或相应双倍标准结算的工时和金额；如果页面把双倍工时另列，要能追溯到同一总工资，不重复计入。
- **Total hours**：所有净工作分钟合计。
- **Hourly rate**：全部工时卡共用一个时薪。
- **Gross pay**：估算的税前工资，不扣税，也不表示实际可领取金额。

**【本次确认的目标】统一时薪**：所有新建/编辑中的卡共用一处费率。假设两张卡各8小时，统一时薪$25、不算加班，则总工时16小时、每张$200、总$400；不存在某张卡单独输入$30的入口。

时薪留空时：继续显示全部工时；金额明确写未设置/需补充时薪，不得默认为 `$0.00`。币种由全局设置决定；以下测试用美元。

### 加班示例：周一到周五

周一到周四每天 `08:00–16:30`，休息30分钟 → 每天8小时。周五 `08:00–18:00`，休息30分钟 → 9小时30分钟。

- 全周净工时：`8 + 8 + 8 + 8 + 9.5 = 41.5小时（41:30）`。
- Weekly 加班：普通40小时、加班1.5小时。
- 时薪$20：普通工资 `$20 × 40 = $800`；加班工资 `$20 × 1.5 × 1.5 = $45`；估算总工资 `$845`。
- **如果关闭加班**：同样的41.5小时全部按$20计算 → `$830`。

### 双周示例

第一周40小时，第二周42小时，时薪$22，Weekly 模式。

- 普通工时80小时，普通工资$1760。
- 第二周超出的2小时按1.5倍计，得到$66。
- 两周合计82小时，工资$1826。
- 不能把两周合并成“超过80小时才计算”的通用规则，更不能把不同员工的工时凑到一起算个人加班。

## 5. 多人/多卡合计｜RPT-05

每张卡先算自己的工时与加班，再在报告末尾汇总。例：

| 员工 | 当天工作 | 无薪休息 | 净工时 | 统一时薪 | 本卡工资 |
| --- | --- | --- | --- | --- | --- |
| Alex | 07:00–15:30 = 8:30 | 0:30 | 8:00 | $25 | $200 |
| Ben | 07:30–16:00 = 8:30 | 0:30 | 8:00 | $25 | $200 |
| Chris | 08:00–17:00 = 9:00 | 1:00 | 8:00 | $25 | $200 |
| **合计** | | | **24:00** | | **$600** |

**重要**：这24小时是三个人的工作量之和，不等于某一个人单日工作了24小时；加班计算须先分人处理。

## 6. 分享链接、只读快照｜RPT-06

- 点击 `Copy share link`，生成**当前数据的只读快照链接**。
- 收到链接的人无需编辑权限即可看报表；无法直接改动发送方浏览器里的草稿。
- 发送方之后修改草稿，**旧链接仍是旧内容**；希望接收人看新版本，需要重新生成链接。
- 【线上可核对】分享快照信息放在链接片段中。任何获得完整链接的人都可查看；快照不支持远程撤销。不要让界面声称“只有指定收件人可见”。
- 打开分享链接而本地已有草稿时，网站有 `Adopt this time card`、`Keep local draft` 的入口。对应的目标行为：**可以选择采纳分享内容或保留本地草稿**，不能无提示覆盖。
- 链接损坏或版本不支持时，应给出错误提示，保留当前草稿。

## 7. 打印、PDF和CSV｜RPT-07

- `Print / PDF` 打开浏览器打印界面，可选择纸质打印或保存PDF；网站不需要单独生成另一套工资算法。
- `Export CSV` 导出明细，至少能核对日期、每段时间、休息、每天净工时、周汇总、加班、金额；按卡保留姓名/客户/项目等已填信息。
- 页面、打印/PDF、CSV与分享快照必须来自**同一份计算结果**，不能出现页面41:30、CSV 41:29的情况。
- 数据无效时先明确错误位置，不能把明显错误的记录当成正确工资报表导出。
- 复制分享链接成功和失败都要有明确反馈；失败时数据不变，可再次尝试。

## 8. 审批回执｜RPT-08

**【线上可核对】**有只读审批快照页面及回执操作，包含 `Reviewer name / Decision / Note / Generate receipt link`，发送方可导入回执链接或JSON。

- 审核人查看的是**当时的只读快照**；可填写姓名、选择审核结论、写备注并生成一个回执链接。
- 发送方可以导入并查看回执；回执应能追溯其关联的工时快照。
- 审批回执**不进行真实身份认证**。它是用于沟通的记录，不等同于具有法律身份验证的电子签章。
- 用户需自行复制、发送快照和回执链接，网站不代发邮件。

## 9. 异常与空值｜RPT-09

| 情形 | 报告怎样表现 |
| --- | --- |
| Name / Client / Project 留空 | 仍可计算；相应标签可省略 |
| Rate 留空 | 显示实际工时，金额提示未设置 |
| 某天完全没有工作 | 可以显示空日期或无工时，不算错误 |
| 某段只有In或Out | 返回编辑，提示补全；不能输出有效工资结果 |
| 出现重叠工作段或休息超限 | 提示具体卡片、日期和时间段，修复后再交付 |
| 用户关闭部分可选字段 | 数据仍保留，按最终报告展示规则输出 |
| 分享链接损坏、复制失败或本地存储失败 | 给出可理解的失败信息，不清空本地草稿 |

| RPT-T02 Weekly | 两周40h与42h，统一$22/h | REG80h/$1760，OT2h/$66，总82h/$1826 |
| RPT-T03 多人 | 三卡分别8小时，统一$25/h | 各$200，总24小时/$600 |
| RPT-T04 修改时薪 | 三卡统一$25→$30 | 各卡金额同步更新，总24小时/$720 |
| RPT-T05 空费率 | 不填时薪，填一天8小时 | 能看8:00，金额提示需填时薪，不显示虚假的$0 |
| RPT-T06 只读 | 打开Report尝试修改时间，随后返回编辑 | Report不能直接改；返回后可修改且保留当前数据 |
| RPT-T07 旧分享不变 | 复制链接→原草稿改时薪和时间→再开旧链接 | 旧链接仍显示原值；新数据需新链接 |
| RPT-T08 本地草稿保护 | 本地有草稿时打开别人的分享链接，点Keep local draft | 本地草稿保留，不被静默覆盖 |

| RPT-T10 审批 | 审核人给只读快照填结论、备注并返回回执，发送方导入 | 可读取同一快照的回执，显示不验证身份 |
| RPT-T11 复制失败 | 在不允许读写剪贴板的环境复制链接 | 明确失败提示；数据不丢，可重试 |

## 11. 需求状态与变更记录

- 【线上可核对】只读快照、打印/PDF、CSV、分享链接、审批回执、工时与加班帮助说明。
- 【旧PRD记载】多卡报告详细字段、字段显示规则、异常处理和双向返回。
- 【本次确认的目标】所有卡统一时薪；各卡不再有独立费率编辑入口。
- 【待核实】历史旧版快照中如有不同费率，如何只读展示；不在新草稿中继续提供多费率功能。
